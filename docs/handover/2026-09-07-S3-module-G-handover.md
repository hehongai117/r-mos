## 7. 这轮攒下的经验（**新窗口最省时间的部分**）

### 7.1 每模块的固定流程（已跑通六次）

1. **先建网**：派 Codex 补行为级测试，**只加测试、不改生产代码**，
   把发现的缺陷按当前真实行为写断言并标注「待改造时处置」；
2. 主审看缺陷清单，**按根因分组**（不是按编号逐条修）；
3. **一批修完**同组缺陷，测试被击穿是预期的；
4. 逐条判断击穿的断言属于「测试固化了漏洞」还是「改错了」；
5. 依赖重测 + 全量测试只增不减；
6. 写结果文档 → 申请口令。

**分组修是关键**：9 类缺陷往往只有 4~5 个根因，逐条修等于多跑几次全量回归。

### 7.2 三类反复出现的缺陷（**新模块先查这三样**）

| 类型 | 表现 |
|---|---|
| **跨校边界缺失** | F、C、B 都有。口径已定：**同校可读是设计，跨校是缺陷** |
| **管辖权粒度过粗** | F-AUTH-04（评分）、G-AUTH-02（force-submit）同型——只问「任一班教过该学生」，不绑定具体对象所属班级 |
| **调用方漏传参数** | 上游把守卫加严，下游没跟上。G-KNOW-01 即此类：**过滤生效了，可用性掉了** |

### 7.3 踩过的坑（重蹈会浪费一轮）

- **守卫可能困在 docstring 里从不执行**（`DELETE /sops/{id}` 发生过）。
  关键字扫描查不出来，**必须用 AST 比对函数体的实际调用**。
- **「零测试失败」先怀疑测试空白**，不是安全信号。多次证实端点根本没有 HTTP 层测试。
- **规则方向会反**：把「仅所有者」套到评分上＝放行学生自评。
  教师职权用 `ensure_teacher_scope_over_student`（所有者本人一律拒绝），
  本人的东西才用 `ensure_write_owner`。
- **错误码三种口径不能混**：资源不存在 404／读越权 404（不泄露存在性）／写越权 403。
- **补字段前先查能否推导**：模块 B 的 4 张无归属表全部可经关联对象推出，省了一次迁移。
  M-01 五表和 `robot_projects` 是真推不出来才补的。
- **架构文档的判定不等于事实**：S1-001 已被实测修正两次
  （「模块划分能表达分层」、「memory fallback 内存合理」）。
